# QA 溝通系列：問對問題、講到重點

> 定位：測試工程師最被低估的核心軟實力——不是會多少工具，是「會提問」和「會講重點」。
> 教學哲學：溝通是可拆解、可練習的技術，不是天生的口才。本課把它拆成兩半：**問對問題**（怎麼問才問得到答案）與**講到重點**（怎麼講才被聽見），再落到 QA 的真實場景。
> 視角：QA IC 講師。每篇 hook 開場、有方法、收尾「帶得走」。
> 狀態：草稿（本地）。一課一檔 `article-Axx/Bxx/Cxx-*.md`。

## 課程定位

- **QA 是溝通密集的工作**：問需求、釐清驗收標準、回報 bug、向上溝通風險、跨團隊協作——測試工程師一天的價值，有一大半是透過溝通交付的。
- **提問與表達是技術，不是天賦**：好問題有結構、好表達有框架。本課把這些框架講清楚，照著練就會進步。
- **兩個方向**：提問是「把資訊要進來」，講重點是「把資訊送出去」。兩者合起來，就是 QA 降低團隊溝通成本的核心能力。

## 課綱（10 課 / 3 模組）

### 模組 A · 提問力（會問才會通）
- **A01** 為什麼「會提問」是 QA 最被低估的核心軟實力
- **A02** 提問前先自助：別當伸手牌
- **A03** 把問題問精準：目標—差異、環境、重現步驟
- **A04** 提問漢堡：核心問題／情境／期待幫助／已做努力
- **A05** 提問的禮儀與反模式：哪些問法會讓人不想理你

### 模組 B · 講到重點（講了才被聽見）
- **B06** 訊息為什麼沒被聽見：讓人接收的五個條件
- **B07** 用「所以」不用「還有」：聚焦單一重點
- **B08** 同理心溝通：講對方在乎的好處、戒掉專業術語

### 模組 C · QA 實戰（把提問與講重點用在測試現場）
- **C09** 回報 bug：把提問與講重點合起來
- **C10** 向上溝通與跨團隊：用風險與重點講品質

## 教學主線

整門課回答一個問題：**測試工程師怎麼用溝通，把自己從「埋頭測試的人」變成「團隊信任的品質夥伴」。**

- 模組 A：把問題問對，你要的答案才會回來。
- 模組 B：把重點講清，你的判斷才會被採納。
- 模組 C：把兩者用在 bug 回報與向上溝通——QA 最高頻、最關鍵的兩個溝通場景。
