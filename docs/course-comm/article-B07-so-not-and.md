# 用「所以」不用「還有」：聚焦單一重點

聚焦聽起來是個大原則，但它常常敗在一個很小的習慣上：講著講著，就「還有……還有……還有……」地補下去。每一個「還有」都覺得很重要，捨不得不講，結果一段話塞了五個重點，等於一個重點都沒留下。

有個極簡的修正：把「還有」換成「所以」。

## 「還有」讓訊息發散，「所以」讓訊息收斂

兩個連接詞，導向完全不同的結構：

- **「還有」是平行堆疊**：A 還有 B 還有 C——所有東西並排，沒有主從、沒有邏輯，對方得自己從一堆並列裡猜哪個重要。
- **「所以」是因果收斂**：A 所以 B——它逼你在資訊之間建立關係，把一堆事實導向一個結論。對方接到的不是一袋零件，是一條清楚的線。

舉個產品史上的經典例子：要描述一台音樂播放器，可以說「它有 5GB 容量、還有鋰電池、還有防刮外殼、還有……」——一堆規格，沒人記得住。也可以說「把一千首歌裝進口袋裡」——直接講那個容量帶來的好處，一句話，記一輩子。後者就是收斂到單一重點的威力。

## 「所以」逼你想清楚「結論是什麼」

改用「所以」最大的價值，不是講出來好聽，是它逼你在開口前先想清楚：這一堆資訊，最後要導向什麼結論？

- 用「還有」時，你可以不用想——把腦袋裡的東西依序倒出來就好。
- 用「所以」時，你被迫做一次收斂——這些事實之間什麼是因、什麼是果、最後要對方記住或決定的是哪一件。

這個「被迫收斂」的過程，正是講重點的核心。很多人講不出重點，不是表達能力差，是根本沒在開口前替對方做這次收斂——把整理資訊的工作，丟給了聽的人。

## QA 場景：把測試結果收斂成一個結論

測試工程師最常需要這個技巧的場合，是回報測試結果。看兩種講法：

> 「還有」版：這個版本我測了登入，還有結帳，還有通知，登入有個小問題，結帳的 VIP 流程會白畫面，通知偶爾延遲，還有我順便看了一下效能……
>
> 「所以」版：這個版本核心流程裡，結帳的 VIP 付款會白畫面、必現，**所以**我建議擋上線、先修這個；其他都是可以下版處理的小問題。

後者一樣涵蓋了測試範圍，但它收斂到一個明確的結論和建議——對方聽完知道「要做什麼決定」。前者倒了一堆資訊，對方還得自己判斷哪個是擋上線的、哪個可以等。一個「所以」，就是你替對方把判斷先做了一輪。

## 帶得走

- 把訊息講散的元兇常是「還有」——平行堆疊，把整理重點的工作丟給聽的人。
- 改用「所以」：建立因果、收斂到單一結論，對方接到的是一條線不是一袋零件。
- 「所以」真正的價值是逼你開口前先想清楚「結論是什麼」——這就是講重點的核心動作。
- QA 回報結果時，用「所以」收斂成一個明確建議（擋不擋上線），替對方先做一輪判斷。

聚焦解決了「講太散」，下一篇解決另一半問題：講對了重點，但用對方聽不懂的語言——同理心溝通。
