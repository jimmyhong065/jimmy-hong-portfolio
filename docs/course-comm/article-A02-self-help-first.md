# 提問前先自助：別當伸手牌

有種同事，遇到任何卡住的事，第一反應是轉頭問人：「這個怎麼弄？」「為什麼壞了？」問題不在他愛問，在於他什麼都沒查就問。久了，大家會在心裡幫他貼一個標籤——伸手牌。一旦這個標籤貼上，你問什麼別人都會少花點心思回。

提問是有前置作業的。問之前做足功課，不只是禮貌，更是讓你的問題值得被認真對待的前提。

## 問之前的自助清單

在把問題丟給別人之前，先走一遍這幾步：

- **搜尋**：把錯誤訊息整段貼進搜尋引擎、查公司內部 wiki／舊的討論紀錄。很多問題別人早就踩過、答案就在那。
- **讀文件**：規格、API 文件、README、FAQ。「文件裡寫了你卻來問」是最快消耗別人耐心的方式。
- **自己試**：能不能自己重現一次、換個條件試試、縮小範圍確認問題到底在哪。動手試過，你的問題會精準很多。
- **看原始碼／設定**（如果搆得到）：有時候答案就在那幾行邏輯或那個設定值裡。

這份清單的重點不是「全部做完才能問」，是「該做的基本功別跳過」。

## RTFM 與 STFW：被這樣回不是被羞辱

如果你問了一個查文件或搜尋就能解決的問題，可能會收到「先讀手冊」「先搜尋」這類回應。別覺得被羞辱——它傳達的是：這個答案很容易取得，你自己查不只更快，還會學得更扎實。

這背後有個對 QA 特別重要的成長觀念：**自己查到的答案，會內化成你的知識；別人直接餵的答案，下次還是不會。** 測試工程師的價值很大一部分建立在「對系統的理解」上，而理解只能靠自己挖。每一次「忍住不馬上問、自己先查」，都是在累積這個理解。

## 自助不是不准問，是問得更值得

把話講清楚：自助的目的不是叫你什麼都自己扛、有問題憋著不問。憋著不問、卡很久不講，對團隊一樣是傷害。自助的真正目的，是讓你問出口的那個問題，是「真的需要別人」的問題——

- 自助後還是卡住 → 這時候問，你已經能說清楚「我查了什麼、試了什麼、卡在哪」，對方一接手就進入狀況。
- 自助的過程 → 經常自己就把答案挖出來了，根本不用問。
- 自助過再問 → 對方知道你不是伸手牌，會更願意、也更高品質地幫你。

判斷準則很簡單：問之前先問自己一句——「這個問題，我有沒有把能自己做的部分做完？」做完了再問，你問的每一題都值得被認真回答。

## 帶得走

- 問之前先走自助清單：搜尋、讀文件、自己試、看原始碼／設定。
- 被回「先讀手冊／先搜尋」不是羞辱——是提醒你這答案自己查更快也學得更扎實。
- 自己查到的會內化成知識，別人餵的下次還是不會——這對靠理解吃飯的 QA 尤其關鍵。
- 自助不是不准問，是讓你問出口的是「真的需要別人」的問題；但也別憋著不問。

做完功課、確定該問了，下一個問題是：怎麼把問題問到精準，讓對方一看就懂。
