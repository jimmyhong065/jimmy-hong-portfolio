# 從指標到數據、從數據到決策：說服高層品質值得投資

測試工程師常有個委屈：明明品質很重要，但要資源、要時間、要人，高層總是不買單。問題往往不在高層短視，在於我們用錯了語言——我們講「我們測得很辛苦」，他們聽的是「這對營收和風險有什麼影響」。

要讓品質被投資，得先學會把品質翻譯成決策者聽得懂的語言：數據、風險、成本。

## 挑對指標：別量虛榮指標

第一步是挑指標。最常見的錯誤是量一堆「看起來很努力」但無法支撐決策的虛榮指標——跑了幾千個案例、寫了多少測試。這些數字大，但回答不了「品質好不好、風險在哪」。

對決策有用的指標，通常圍繞幾個方向：

- **逃逸缺陷**：多少 bug 是上線後才被使用者發現的。這直接反映防護網的漏洞，也最容易換算成業務影響。
- **缺陷修復成本與時間**：問題從發生到修好花多久、花多少。能凸顯「早抓 vs 晚抓」的成本差。
- **線上事故的頻率與影響**：多久出一次事、每次影響多少用戶／營收。
- **關鍵品質面向的達成度**：可靠性、效能等重心面向，離目標多遠。

挑指標的原則：**每個指標都要能連到一個決策。** 量了卻不會改變任何決定的指標，就是浪費。

## 把數據翻譯成風險與成本

有了指標還不夠，數字本身不會說服人。要把數據翻譯成決策者在乎的東西：

- 不要說「逃逸缺陷上升了 30%」，要說「上線後才抓到的問題變多，代表我們在用最貴的方式修 bug，而且使用者正在替我們測試」。
- 不要說「回歸測試要三天」，要說「每次發版我們要押三天，這是我們上線速度的天花板，自動化能把它壓到幾小時」。
- 不要說「沒時間測效能」，要說「我們沒驗過尖峰承載，這是一個我們完全沒蓋的風險，出事的代價是整個服務在高峰當掉」。

核心是把「測試的活動」翻譯成「業務的風險與成本」。高層不需要懂測試，他們需要懂「不投資的後果是什麼」。

## 用數據做決策，不是用數據邀功

最後一個心態轉換：指標不是拿來證明 QA 很努力的，是拿來幫團隊做更好的決策的。

- 數據顯示某模組逃逸缺陷特別高 → 決策：那塊要加強覆蓋或重構，而不是平均加人。
- 數據顯示回歸是上線瓶頸 → 決策：投資自動化的投報率算得出來，不再是「感覺該做」。
- 數據顯示某類風險從沒被測 → 決策：知情地補上，或知情地接受。

當品質投資能用數據算出投報率，它就從「QA 一直吵著要的東西」變成「一個理性的商業選擇」。這是測試工程師影響力的天花板所在——不是測得多好，是能不能用決策層的語言，讓品質變成被理解、被投資的事。

## 帶得走

- 高層聽的是風險與成本，不是「我們測得多辛苦」。
- 挑指標的原則：每個指標都要能連到一個決策；別量虛榮指標。
- 把數據翻譯成業務語言：逃逸缺陷＝用最貴方式修 bug、回歸三天＝上線速度天花板。
- 指標是用來做決策，不是用來邀功——讓品質投資變成算得出投報率的商業選擇。
