# 軟體品質工程系列 — 從交付觀念到職涯全局觀

> 定位：比 API／效能課更廣的「品質工程全局觀」課——不只講「測什麼」，而是品質怎麼想、怎麼設計、怎麼管理、怎麼證明價值、怎麼面對 AI。
> 教學哲學：**以終為始**。品質不是測試階段的事，是從需求到交付、再到上線後的一整條鏈路。觀念與方法論為主，必要時給可落地的清單與範本。
> 視角：QA IC 講師。每篇 hook 開場、有方法、收尾「帶得走」。
> 狀態：草稿（本地）。一課一檔 `article-Exx-*.md`。

## 課程定位

- **全局觀優先**：測試工程師的天花板不是會多少工具，是能不能看懂整個交付鏈路、在對的位置放對的防護網。
- **以終為始**：先問「這次交付要達成什麼」，再回推要驗什麼、怎麼設計、怎麼管理。
- **品質可被管理、可被證明**：用指標與數據把「品質值得投資」講給高層聽，是資深 QA 的核心能力。
- **面對 AI 不販賣焦慮**：AI 改變的是工具與分工，不是品質的根本。務實看 AI 怎麼幫測試、AI 產品怎麼測、職涯怎麼走。

## 教學主線

整門課回答一個問題：**測試工程師怎麼從「找 bug 的人」變成「能定義並守住品質的人」。**

- 模組 0–1：品質的起點是需求與目標，不是測試案例。
- 模組 2：核心方法論——計畫、設計、執行、左右移。
- 模組 3：品質要能被管理、被量化、被決策層看見。
- 模組 4–5：自動化與 AI 改變工具，但不改變上面的根本。
- 模組 6：把全局觀換成職涯價值。
